# Бесплатный демо-деплой Sushi Lab

Этот вариант использует Cloudflare Pages для сайта, Render Free для API, Neon Free для PostgreSQL и Cloudflare R2 для фотографий. Это демо: бесплатный API может засыпать, а бесплатные планы не дают гарантий доступности и резервного копирования. Не используйте его как надёжную production-платформу для реальных заказов.

## 1. Подготовить код

Разместите проект в GitHub и подключите этот репозиторий к Render и Cloudflare Pages. Не публикуйте `.env`, пароли, JWT/VAPID-ключи, ключи R2 или локальную базу `sushi_cafe.db`.

## 2. Создать PostgreSQL в Neon

Создайте бесплатный проект и скопируйте PostgreSQL connection string. На Render задайте его переменной `DATABASE_URL` как секрет. Backend автоматически использует драйвер psycopg 3. Новая база заполнится схемой и стартовым каталогом при первом запуске; заказы из локальной SQLite автоматически не переносятся.

## 3. Создать API в Render

Создайте Web Service из `render.yaml` и задайте обязательные переменные:

- `DATABASE_URL` — строка Neon.
- `ADMIN_USERNAME` и `ADMIN_PASSWORD` — новые уникальные данные, не `admin/admin`.
- `CORS_ORIGINS` — точный origin сайта, например `https://sushi-lab.pages.dev`, без завершающего `/`.

Render создаст `JWT_SECRET`. После публикации проверьте `https://<имя-api>.onrender.com/api/health`.

## 4. Включить push-уведомления

Сгенерируйте VAPID key pair локально, например командой `npx --yes web-push generate-vapid-keys`. В Render задайте `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` и `VAPID_SUBJECT` (например, `mailto:ваш-рабочий-email@example.com`). Не отправляйте приватный ключ в чат и не добавляйте его в файлы проекта.

После публикации сайта войдите в `/admin`, откройте Dashboard и включите уведомления на телефоне/браузере, где хотите их получать. На той же панели их можно выключить. Уведомление содержит только номер заказа и сумму, не клиентские контактные данные. На iPhone сначала добавьте сайт на главный экран; push требует HTTPS и поддерживается на iOS 16.4+.

## 5. Сохранить загружаемые фото в R2

Создайте Cloudflare R2 bucket и включите публичное чтение фотографий через публичный R2 URL или собственный домен. Создайте R2 API token только с правом записи объектов в этот bucket. В Render задайте:

- `R2_ENDPOINT_URL` — `https://<account-id>.r2.cloudflarestorage.com`.
- `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY` — ключи токена.
- `R2_BUCKET` — имя bucket.
- `R2_PUBLIC_BASE_URL` — публичный URL без завершающего `/`.

Без этих переменных загрузка новых фото в production отключена с понятной ошибкой. Не используйте временный локальный диск Render для постоянных изображений.

## 6. Опубликовать frontend на Cloudflare Pages

Подключите репозиторий как Pages project. Укажите root directory `/`, build command `npm run build` и output directory `dist`. Добавьте build variable `VITE_API_BASE_URL=https://<имя-api>.onrender.com`, затем запустите deploy. Установите в API `CORS_ORIGINS` фактический адрес Pages.

Можно попробовать адрес `sushi-lab.pages.dev`, но его доступность и возможность регистрации не проверялись. Бесплатный `pages.dev` — технический адрес, а не отдельный собственный домен; красивый `.com`/`.kg` обычно оплачивается отдельно.

## Ограничения и приватность

- Существующие локальные заказы остаются в `sushi_cafe.db`; их перенос не включён, чтобы не отправлять персональные данные клиентов в облако без отдельного согласования.
- Бесплатный Render может усыплять API, поэтому первое открытие/оформление заказа после простоя может задержаться.
- До передачи сайта заказчику замените бесплатные демонстрационные тарифы на управляемый production-хостинг, настройте резервные копии, миграции и мониторинг.
